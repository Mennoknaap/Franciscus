# Architecture

Core plumbing that most features touch, one way or another. Feature-specific behavior lives in its own doc — see the routing table in the root `CLAUDE.md`.

## Routing & hosting

`app.routes.ts` uses `provideRouter(routes, withHashLocation())` — hash-based routing is required because the app is served from a GitHub Pages subpath (`/Franciscus/`) via the `gh-pages` branch, not a server that can rewrite arbitrary paths.

## Feature module pattern

Most routed features pair a standalone component (e.g. `home.ts`) with a same-folder `*.module.ts` that only exists to declare/import that component's dependencies (Angular Material modules, etc.) and is attached via the route's `providers:` array (see `app.routes.ts`). Some newer routes (`admin`, `liedjes`, `poop-app`) skip this and use plain `loadComponent`. When adding a feature, check whether it needs its own Angular Material imports before deciding which pattern to copy.

## Generated API client

`src/app/apiclients/fransapi.client.ts` is generated by NSwag from the backend's OpenAPI spec, configured in `src/app/apiclients/api.client.nswag` (points at `https://localhost:7225/swagger/v1/swagger.json` — the backend must be running locally to regenerate). Do not hand-edit this file; regenerate it via NSwag when the backend API shape changes. The base URL is injected via the `FRANS_API_BASE_URL` token, wired to `environment.apiUrl` in `app.config.ts`.

## Environments

`environment.ts` (dev, local backend) and `environment.prod.ts` (prod, live backend) both also carry the shared Firebase project config — the Firebase project is the same across environments, only the FransApi `apiUrl` differs. `environment.prod.ts`'s `vapidPublicKey` must match whatever private key is configured on the Pi — see [push-notifications.md](push-notifications.md).

## PWA

Service worker (`ngsw-config.json`) is enabled only outside dev mode (`app.config.ts`), registered with a 30s stability delay. This means a deployed CSS/JS fix may not be visible until the PWA is fully closed and relaunched from its home-screen icon, not just refreshed.

## Home tiles (`AppCard`)

`AppCard` (`home.ts`) supports an optional `icon` (Material icon name) as an alternative to `image`, rendered by `home.html`, for tiles that don't have (or don't need) a dedicated PNG asset — used by the "Liedjes" tile. Tiles are also gated per-app via `requiresAppKey` — see [app-access.md](app-access.md) for the full access-control system.
