# Poeplog (`poop-app`)

`poop-app.ts` is the actual "Poeplog" feature (home tile and page title both say "Poeplog", not "Top Secret" — that name is gone from the codebase entirely). A WhatsApp-style chat feed (`.chat-bubble`, right-aligned/green via `.mine` for your own entries, left-aligned/white with a sender-name line for everyone else's) shows every logged "hij heeft gepoept 💩"/"hij heeft geplast 💦" event, fetched from `GET /poop-app/log` on init; two large buttons at the bottom (`logPoop()`/`logPee()`) call `POST /poop-app/log`, which both appends to the local `log` signal and — server-side — pushes a notification to everyone else (not yourself; see the API repo's `docs/poop-app.md`).

`PoopLogType` is generated by NSwag as a plain `0 | 1` union type, not a real TS enum (same as the existing `RoleType`), hence the local `POOP_LOG_TYPE_POOP`/`POOP_LOG_TYPE_PEE` constants instead of referencing enum members.

Note: `PoopLogEntry.createdAt` comes back from NSwag as a `dayjs.Dayjs`, not a native `Date` — format it with `dayjs(...).format(...)` like `child-detail.ts` already does, not Angular's `date` pipe (which expects a real `Date`).

The original `sendTestNotification()` push-delivery diagnostic (5-second countdown, `<details>` section) has been removed along with its backend endpoint now that the real logging flow itself proves push delivery works.

## Admin actions

All admin-only actions (`clearLog()`, the two sticker-upload triggers) live behind a single `mat-menu` (`more_vert` icon, only rendered when `isAdmin()` — `user()?.role === 0`, same check as `admin-auth-guard.ts`) rather than being separate always-visible buttons — same "one overflow menu per role, not one button per action" pattern as `admin.html`'s per-user menu.

`clearLog()` opens the shared `components/confirm-dialog.ts` (see [platform/dialogs.md](../platform/dialogs.md)) before calling `DELETE /poop-app/log`; there's no undo. Each bubble also gets its own small `deleteEntry(id)` (×) button whenever `canDelete` (your own entry, or any entry if you're admin), gated behind the same shared `ConfirmDialog`.

## Auto-scroll to the newest message

`scrollToBottom()` uses `setTimeout(fn)` (a macrotask), not an `effect()` reading the `log` signal. An effect-based approach (`effect(() => { this.log(); const el = this._chatLog()?.nativeElement; ... })`) was tried first and silently never worked — logging confirmed the effect fired, but `_chatLog()`'s `nativeElement` and a populated `log()` never lined up within the same invocation, for reasons not fully root-caused (possibly an interaction between zoneless change detection's scheduling and this signal-based `viewChild` query).

Calling `scrollToBottom()` explicitly right after `this.log.set(...)`/`this.log.update(...)` (in the `getLog()` subscribe and in `logAction()`'s subscribe) and deferring the actual scroll via `setTimeout` — which runs after Angular's zoneless CD has flushed the DOM for that signal write — works reliably. **If another list-plus-scroll feature hits the same "effect never seems to see the latest signal value" symptom, reach for an explicit post-write callback before spending time on the effect/viewChild timing.**

## WhatsApp-style date separators

("Vandaag"/"Gisteren"/Dutch day name/full date, via `dateLabelFor()`) are computed per-entry in `toViewEntry()` but only actually *shown* (`showDateSeparator`) when `markDateSeparators()` — called after every list mutation (initial load, appending a new entry, deleting one) — finds this entry's `dateKey` differs from the previous entry's. Deleting an entry re-runs `markDateSeparators()` rather than just filtering it out, specifically so removing the first message of a day doesn't leave the *next* day's messages without their own separator (the deleted entry might have been the one carrying it).

This is also why the global Dutch dayjs locale exists (`main.ts`: `import 'dayjs/locale/nl'; dayjs.locale('nl')`, a process-wide side effect run once at bootstrap) — `date.format('dddd')` needs it for a day name like "dinsdag" rather than "Tuesday"; this incidentally also makes `child-detail.ts`'s existing `formatDate()` output Dutch month names now, which it never explicitly configured before.

## Sticker mode

Sticker mode is a purely local, unsynced display preference — it never changes what gets logged. `displayMode` (`'text' | 'sticker'`, persisted to `localStorage['poeplog-display-mode']`) only controls how *this browser* renders existing/new `PoopLogEntry` rows: in `'sticker'` mode, an entry renders `<img [src]="stickerUrlFor(entry.type)">` instead of `.chat-text` whenever a sticker has been uploaded for that `PoopLogType` (falls back to text otherwise); one person viewing in sticker mode has zero effect on what anyone else sees, or on what `POST /poop-app/log` actually records.

`poopStickerUrl`/`peeStickerUrl` are fetched once via `GET /poop-app/stickers` on init and prefixed with `environment.apiUrl` (same relative-path-from-API convention as `Child.profilePicture` in [liedjes.md](liedjes.md)). Uploading a sticker (`uploadPoopSticker`/`uploadPeeSticker`, hidden file inputs, admin-only UI matching `isAdmin()`) calls `POST /poop-app/stickers/{type}` and is itself global/shared — only *viewing* stickers is a personal toggle, the sticker images themselves are the same for everyone once uploaded.

`.chat-sticker` renders at a **fixed** 100×100px with `object-fit: contain`, not sized to the source image — admins upload arbitrary photos (any resolution/aspect ratio, not pre-cropped sticker art), so letting the image size itself blew up the whole chat feed for a tall portrait photo.

Animated GIF stickers work with no extra code: the upload accepts `image/gif` (same as the API's other content-type checks), and the rendering `<img>` tag animates GIFs natively in the browser like any other `<img src="....gif">` — this isn't something the app controls either way.

## Sticky layout

`poop-app.html`'s root is a fixed-height flex column (`.poop-app-page`, `height: 100dvh; overflow: hidden`), not the page's normal document flow. `app-title` + the mode toggle + admin sticker-upload buttons live in `.poop-app-header` (`flex-shrink: 0`), the "Gepoept"/"Geplast" buttons in `.log-actions` (also `flex-shrink: 0`), and only `.chat-log` (`flex: 1; min-height: 0; overflow-y: auto`) scrolls — the `min-height: 0` is required, a flex child otherwise refuses to shrink below its content's height and the whole page scrolls instead of just the log. Without this structure the entire page (header, toggle, buttons, everything) scrolled together as one long document, which is the opposite of a chat app's expected feel (header and send-buttons pinned, only messages scroll).
